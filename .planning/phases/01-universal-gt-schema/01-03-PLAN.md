    `ValidationConfig(BaseModel)`:
    - `require_reading_order: bool = False`
    - `require_text: bool = False`
    - `require_bbox: bool = True`
    - `confidence_threshold: float = Field(default=0.8, ge=0.0, le=1.0)`

    `GTProfile(BaseModel)`:
    - `name: str = "base"`
    - `description: str = ""`
    - `inherits: str | None = None` — which profile this extends (for documentation; actual layering done in loader)
    - `schema_version: str = SCHEMA_VERSION`
    - `spatial_labels: set[str] = Field(default_factory=lambda: {"text_block", "footnote_area", "page_header", "page_footer", "page_number", "section_header"})`
    - `semantic_types: set[str] = Field(default_factory=lambda: {"footnote", "citation"})`
    - `formatting_types: set[str] = Field(default_factory=set)`
    - `document_types: set[str] = Field(default_factory=lambda: {"metadata"})`
    - `validation: ValidationConfig = Field(default_factory=ValidationConfig)`
    - Method: `is_label_enabled(category: str, label: str) -> bool` — checks if a label is active in this profile. Category is one of "spatial", "semantic", "formatting", "document". Returns True if label is in the corresponding set.
    - Method: `enabled_labels() -> dict[str, set[str]]` — returns all enabled labels grouped by category
    - Config: `model_config = ConfigDict(extra="allow")` for project-level custom fields

    `ProjectConfig(BaseModel)`:
    - `profile: str = "base"` — which default profile to use
    - `additional_spatial_labels: set[str] = Field(default_factory=set)`
    - `additional_semantic_types: set[str] = Field(default_factory=set)`
    - `additional_formatting_types: set[str] = Field(default_factory=set)`
    - `additional_document_types: set[str] = Field(default_factory=set)`
    - `disabled_labels: set[str] = Field(default_factory=set)` — labels to remove from the profile
    - `validation: ValidationConfig | None = None` — override validation settings

    **scholargt/config/loader.py**: Config loading with layered YAML.

    `PROFILES_DIR` = Path pointing to scholargt/config/profiles/

    `load_profile(profile_name: str = "base", project_config_path: Path | None = None) -> GTProfile`:
    1. Load `profiles/base.yaml` via PyYAML
    2. If `profile_name != "base"`, load `profiles/{profile_name}.yaml` and overlay (update) on base
    3. If `project_config_path` provided, load it as `ProjectConfig` and apply:
       - Merge `additional_*` label sets into profile sets
       - Remove `disabled_labels` from all label sets
       - Override validation if provided
    4. Validate final merged dict via `GTProfile.model_validate(config_dict)`
    5. Return GTProfile

    `list_profiles() -> list[str]`: List available profile names by scanning profiles/ directory.

    `get_profiles_dir() -> Path`: Return path to built-in profiles directory.

    Do NOT use pydantic-settings `YamlConfigSettingsSource` for the layered loading — it's simpler and more explicit to do the merge manually with PyYAML since we need custom merge logic (additionals, disabled). Use pydantic-settings only if you find a clean pattern; otherwise, manual YAML loading with PyYAML is fine (it's already installed). The research recommended pydantic-settings but the actual merge logic (additionals, disabled) goes beyond simple source layering.

    Note: pyproject.toml should have pydantic-settings added to dependencies via `uv add`. If it's added to optional dependencies instead, use `uv add pydantic-settings` to add to core deps, OR add to an optional `gt` group and document. Either way is acceptable — use your judgment on whether it should be a core dep or optional dep. Given scholargt is a separate package conceptually, it could go in `[project.optional-dependencies] gt = [...]` but a core dep is simpler for now.
